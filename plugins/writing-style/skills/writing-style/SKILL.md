# 文件寫作風格

本文只放選路、衝突裁決、核心邊界與驗收。低層寫法與正反例在 `references/examples.md`：轉分享版時必讀其對應小節，其餘卡住或自檢抓到問題時載入。

## 成功標準與交付前驗收

六個目標，同時是交付前要跑的六個驗收問題。**驗收不是可選步驟。**

| 目標 | 驗收 |
| --- | --- |
| 同步層先講完 | **同步層**（標題之後、第一個 `##` 之前）最多 5 個主張，hook 量 400 字元：現況或結論、已決定的事、要讀者做的事、沒有行動需求的人在哪停。不得出現本文件首次定義的術語，不用多層子句把主張塞進一句。放不進去的一律後置到小節，不是刪掉 |
| 掃過一遍就拿得到核心資訊 | 只看標題與每段第一句，拿得到嗎？有結論的先給結論，需要行動的給下一步 |
| 中斷後回得來 | 從任一小節開頭讀起，靠標題與該節入口能重新定位嗎？ |
| 掃讀取得的資訊不失真 | 每個結論的數字、條件、適用範圍、因果方向與不確定性有沒有保留？限定語與方法限制是不是緊貼著它所限制的主張？ |
| 不熟的名詞不擋路 | 哪些術語是從來源資料繼承來的？讀者不熟的有沒有白話說明？該留的正式名稱有沒有留著當查詢入口？縮寫、代號首次出現有沒有定義（表格儲存格也算）？ |
| 主線不被次要內容淹沒 | **逐個預設展開的區塊**（段落、條列、表格，不是逐節）指出它怎麼支持讀者完成當前的閱讀目的——做決定、執行步驟、判斷風險、正確理解結果、建立完成當前任務不可缺的最小心智模型都算。說不出來的刪掉或移出主線 |

另外三項：

- **最短成功路徑**（教學與操作型文件）：讀者在讀完背景、詞彙表、完整範例與故障排除之前，是不是已經看到第一次能成功的路徑？
- **最長區塊抽查**：重讀全文最長的三個段落與三個條列項目。第一句已經給出可用結論時，後面每句都要在補必要條件、理由或動作。
- **標點與用語**：分號、破折號、正文裡串接敘事的 ＋、＝、／、→、`&`；中國用語過濾（詞表見 `references/taiwan-terms.md`）。

`references/examples.md` 另有 AI 常犯的五個問題（開頭冗言、段尾摘要、虛詞堆砌、裸的一句一段、局部補丁堆疊）的判斷細節。

## 規則衝突時的優先序（仲裁表）

**衝突時照這張表判，不自行權衡**（實例見 `references/examples.md`）。

| 衝突 | 優先 | 怎麼做 |
| --- | --- | --- |
| 白話 vs 忠於來源 | 忠於來源 | 換說法可以，不改數字、條件、適用範圍、因果方向與不確定性。白話版無法保留精確度時兩個都寫 |
| 限定語 vs 一個項目一個主張 | 限定語 | 放不下就寫成「結論 ＋ 緊接的限定說明」或拆成段落，不刪限定語 |
| 必要前提 vs 精簡 | 必要前提 | 讀者完成**當前任務**所需的前提、關係與步驟一律明寫。只保護當前任務——未來可能用到的背景、其他情境的例外改用內容分流處理 |
| 同步層預算 vs 完整論證 | 預算 | 同步層只放結論與行動；論證、證據、展開的限定條件進後段小節。會改變結論方向的限定語（「只在 X 情況成立」）留在同步層那一句裡，算同一個主張 |
| 自我完整 vs 不重複 | 自我完整 | 不讓讀者為了理解當下這段而回查前文；必要的重述是允許的。自我完整的單位是小節，不是任意一段 |
| 重要但書 vs 結論先行的排序 | 重要但書 | 但書緊貼它所限制的那個主張，不移到文末；只有查證細節與原始材料進附錄 |
| 通用寫作慣例 vs 目標讀者的實際需求 | 目標讀者 | 讀者的任務、知識與實際回饋優先於任何 style guide，也優先於本文的預設語氣與文體 |

## 動筆前：認定讀者與任務

- **先認定單一目標讀者，以及他讀完要做的事**（拍板、對齊、分派、照做、學會操作）。這是寫作者的判斷，不一定要寫進成品。多讀者、非線性查閱的參考型文件保留彈性。
- **對非實作讀者，用讀者能觀測的結果取代實作機制名詞**；術語對這位讀者是最清楚的捷徑時就保留。
- **整段服務別的讀者時**，移到對應文件、原處留一句連結。

預設語氣是「懂技術的同事在跟主管和團隊說明狀況」：專業白話。**這是內部技術文件的預設**，對外依實際讀者調整（校準對照表見 `references/examples.md`）。

- 內部完整版要轉成分享版時，必讀 `references/examples.md` 的分享版小節（裁切六步、人稱跟流通範圍、詞彙白名單、外流檢查）。
- **分開標示事實、推論、建議、已決定的事、還不知道的事**。事實與推論標證據強度（已觀測、有來源支持、待查證），建議與決定標狀態（待確認、已定案）。
- **事件報告**焦點放在系統和流程不放在個人；action item 的 owner 已知就寫，未知標「待指派」，不猜測。

## 內容分流：先決定留不留，再決定怎麼寫

文件分兩層。**同步層**是開頭那一塊（見成功標準第一列）；**展開層**是其餘全部，依下表決定順序與去處：主線緊接同步層之後、條件式與查閱型後置、背景刪掉或移設計文件。被同步層擠出的內容一律落到展開層，不是消失。多讀者的文件同步層共用，各角色在展開層有自己的入口小節，不各產一份。

| 類型 | 判準 | 處理 |
| --- | --- | --- |
| 主線 | 完成當前任務要用的判斷、步驟、必要前提，正確理解結果所需的說明，以及**會改變當前判斷或操作**的成本、安全、正確性限制 | 保持可見，排在最前面 |
| 條件式 | 只有某些情境才用得到 | 可見處留觸發條件與一句摘要，細節延後 |
| 查閱型 | 讀者會回頭查的內容（故障排除、錯誤訊息、參數表） | 放主線後方或獨立文件 |
| 背景與內部機制 | 解釋「為什麼這樣設計」，不影響讀者完成任務 | 刪掉，或移到設計文件 |

**教學與操作型文件的硬規定**：先給完成最小可用結果的路徑。詞彙表、架構說明、完整情境與故障排除不得擋在第一次成功之前，除非少了它會造成操作失敗或重大風險。真正必要的前置條件仍放在操作之前——這條管的是「背景不擋路」，不是「步驟最少」。

模板是鷹架不是監獄：某個 section 不適用就省略，不填「無」湊字數；不加為了完整而存在的節、不重複總結、不寫樣板句（Anthropic 對寫檔文件的官方校準：cover the substance, but do not pad with filler sections, redundant summaries, or boilerplate）。

摺疊（`<details>`）只是後置內容的呈現方式之一，且是選配；條件與禁令見 `references/examples.md`「摺疊的條件與禁令」。

## 掃讀預設與結構選擇

**預設採掃讀型**。

文體判準跟著**讀者的使用方式**走，不是跟著內容怎麼產生：

- **反覆查閱、跨文件比對的文件一律掃讀型**：報告、清查、週報、會議摘要、狀態回報、決策紀錄、狀態檔、規格、稽核。
- **論述型是例外**，只用於一次性完整閱讀的說服文：裁決前的說服論證、決策 memo、設計文件的權衡章節、部落格文。

- **掃讀型（預設）**：結論句在前，接著是一個項目一個完整主張的條列；段落降到最少，因果說明先改寫成「結論一句＋理由條列」，改寫會斷邏輯才留段落。
- **論述型（例外）**：段落承載因果與權重；條列留給並列事項。

段落長度不設固定句數（一句或超過六句都可能合理）。判準是**一段承載一個推論單位**：同時裝了兩條推理鏈、或讀者必須回頭才能理解時就拆開。

| 內容型態 | 形式 |
| --- | --- |
| 多屬性的結構化比較（root cause 分析、排除的假設、action items、各角色重點） | 表格；儲存格精簡，解釋寫在表格外 |
| 可重排、同質、並列的離散項目 | 條列；「重排順序不改變意義」才算並列，順序重要時用編號清單 |
| 因果推導、權衡取捨、論證推理 | 結論句＋理由條列，斷邏輯才留段落——拆成無結構的 bullet 會砍掉連接詞、斷掉邏輯 |

表格與條列的門檻、過度條列的警訊、文件層級的排序：見 `references/examples.md`。

## 掃讀但不失真

掃讀型的形式壓力會把有條件的發現壓成無條件斷言——條件、樣本範圍、限定語塞不進一行標題句。三條核心邊界：

- **一個項目承載一個完整主張**（跟段落的「推論單位」是同一個概念，尺度不同）。「一行」會隨螢幕寬度換行，不是語意單位。
- **條件、範圍、數字、不確定性是主張的一部分**，不是可以刪的背景。不砍連接詞、不砍主詞、不用抽象名詞堆疊代替完整敘述。
- **不用符號取代語意關係**，也不為了維持全條列而拆斷論證。

「短」的壓力只落在同步層；展開層的完整性由上面三條保護，兩者不互相讓步。

## 專有名詞、縮寫與代號

**研究型與調查型報告的預設：讀者不熟這個領域**。委託研究本身就是不熟的訊號；交付時會不自覺沿用來源文件的用語，要主動檢查。

處理階梯，由上而下試：

1. **能換成日常說法且不失真，就換掉。** 判準：有沒有同義的日常字？
2. **換不掉就保留術語，首次出現處給一句白話說明。** 換不掉的正當理由：白話版會失真、讀者要拿這個詞去搜尋或跟人討論、那是該領域的固定用法。
3. **大型文件才建 glossary**，短報告用行內首次說明即可。

縮寫、代號首次出現處給定義，表格儲存格與跨文件都不豁免。其餘細則見 `references/examples.md`「術語處理」節。

## 中文行文

- **不硬翻成台灣工程實務不用的生造中文**：Log、Endpoint、Sprint 這類保留原文。保留英文之後，讀者不熟時一樣要補白話說明。
- 主動過濾中國用語（詞表見 `references/taiwan-terms.md`）。
- 標點、空格與句型細則見 `references/examples.md`。
