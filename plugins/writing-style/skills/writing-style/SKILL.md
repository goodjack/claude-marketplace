# 文件寫作風格

細節在 `references/`：`examples.md` 正反例、`doc-types.md` 各類文件骨架、`diagrams.md` 畫圖（要畫才讀）、`taiwan-terms.md` 用語詞表。

## 0. 目標、底線與必守條款

- **目標是好讀**：讀者省力地拿到需要的內容，找得到、看得懂、用得上。
- **底線是不失真**，只管會改變讀者判斷或行動的內容，也就是**五種限制**：
  1. 適用範圍：哪群人、哪段期間、哪些條件。
  2. 結論性質：相關還是因果、往回驗算還是預測。
  3. 證據可靠程度。
  4. 數字的必要背景：比較對象、期間、單位。
  5. 會改變判斷或行動的例外與不利結果，不能只留有利的。
- **底線以外，規則衝突時好讀勝**（第 7 節）。

必守條款：

1. 開頭有硬上限（第 2 節），放不下的移到後面小節，不刪。
2. 每個主張都對照五種限制，適用的用短白話緊貼主張交代。
3. 分成兩部分時，給人讀的部分能單獨正確使用，且與查證用的部分不矛盾。
4. 交付前跑第 6 節每份都跑的驗收，做不到的標待驗。

## 1. 先認定閱讀任務

- 單一目標讀者與他讀完要做的事：決定、操作、理解或查閱。這是寫作者的判斷，不一定寫進成品。
- 需求不明時，只有不同解讀會寫出實質不同的文件才先問，問題放在已完成內容的末尾。否則寫明假設繼續。
- 解釋多深看讀者對這個題目的熟悉度，不看職稱。研究與調查型產出預設讀者不熟該領域。
- 對非實作讀者，用他看得到的結果取代實作機制名詞。
- 預設語氣是懂技術的同事向主管與團隊說明狀況（examples「語氣校準」）。
- 平台不明時預設用文字，需要圖時可附 Mermaid 並給完整文字替代（可調預設，見 `diagrams.md`）。
- 專案或團隊的寫作規範優先於本 skill，本 skill 優先於通用慣例（擴充方式見 examples）。

## 2. 安排最少必要內容

**開頭**（同步層：標題後到第一個 `##` 前）最多 5 個主張，hook 量 400 字元。第一句交代讀者的決定或動作狀態：已定案、待決、要做什麼或不用行動。再依需要補現況或結論、沒有行動需求的人在哪停。待決事項多時，讓讀者知道全部範圍並能直接跳到清單。每個主張帶著自己的數字、條件與不確定性。超過上限就移走整個低優先主張，不拆限定語、不用多層子句硬塞。不出現本文件首次定義的術語。

其餘內容依類型決定去處：

| 類型 | 判準 | 處理 |
| --- | --- | --- |
| 主線 | 完成當前任務需要的判斷、步驟、前提與理解結果所需的說明；會改變判斷或操作的成本、安全、正確性限制；會影響結論、信心或行動的未知 | 緊接開頭 |
| 條件式 | 只有某些情境用得到 | 留觸發條件與一句摘要，細節後置 |
| 查閱型 | 讀者會回頭查（故障排除、參數表） | 主線後方或獨立文件，可摺疊（條件見 examples） |
| 背景 | 不影響完成任務的設計理由 | 刪掉或移到設計文件 |

- 刪與移分開：理解需要的內容只移不刪。
- 教學與操作型先給最短成功路徑：詞彙表、架構、完整範例與故障排除不擋在第一次成功之前。必要的前置條件、規則的例外與未定的邊界，放在讀者套用之前。
- 同一個事實在主線只完整寫一次，其他地方一句帶過或指向該節，結尾不重講。主線留判斷所需的證據與限制，完整時間、錯誤碼、逐筆紀錄放查證用的部分。
- 各類文件的骨架見 `doc-types.md`，是鷹架不是範本：不適用的節省略，不建空結構，不重複總結，不寫樣板句。
- 要讓人理解、複述或轉述，又要保留精確版時才分兩部分：給人讀的在上，分隔線加「以下供查證，不必讀」，查證用的在下。主要拿來查的文件（狀態、規格、決策紀錄）不分。長報告的摘要要能脫離全文獨立閱讀。

## 3. 選擇呈現方式

反覆查閱或跨文件比對的文件（報告、會議摘要、狀態、規格、決策紀錄）一律掃讀型，論述型只限一次讀完的說服文。**掃讀型的判準**：只讀標題與每段首句，就取得當前任務需要的資訊且不誤解。分析與決策型給判斷，操作型給動作，查閱型給定義或查找入口，不必每段硬加結論。

| 內容 | 形式 |
| --- | --- |
| 可重排的並列項目 | 條列，每項自我完整 |
| 有順序的步驟 | 編號清單 |
| 多屬性比較、要查確切數字 | 表格，儲存格精簡 |
| 分支、迴圈或系統關係，且圖能降低理解成本 | 圖 |
| 要看趨勢、模式或例外的數字 | 圖表 |
| 強調先後的事件，三件以上 | 時間線，步驟不用 |
| 因果推導、權衡、連續推理 | 短段落 |

- 一段聚焦一個問題，不設固定句數，裝了兩條推理鏈就拆。
- 短文件不分節。讀者需要跳讀或回查才加標題，讓他知道這節回答什麼，可寫成心裡的問題或結論。
- 同一清單的格式一致。粗體只給讀者需要一眼找到的結論、動作或定位詞，粗體開頭的條列可用但不是預設。
- 同一份文件的視覺記號一致，需要解讀的記號（線型、顏色）附圖例，顏色不單獨承載意義。

對話裡的回覆：短回覆用段落、不加標題，第一句交代答案、現況與要不要行動。面向多到讀者要逐項對照，才用條列或表格。長任務的最後一則要能單獨讀懂。

## 4. 寫得清楚且不失真

**證據標示分三個面向，各用一套詞**：

- 資訊類型：觀測事實、推論、建議、已決定。
- 推論與結論的可靠程度：已驗證、初步跡象、結果不一致、資料不足。
- 建議的決定狀態：待確認、已定案。

怎麼標與怎麼寫：

- 主要判斷（開頭、小節首句、支撐建議或決定的判斷）就近標。同一小節內條件與強度完全相同的可共用一次標示，不同就各自標，引入新假設的次要判斷也要標。
- 醒目的位置不能比材料更確定：標題、粗體句、圖標題、方框與箭頭都受五種限制約束。只看到先後就寫先後，不升成因果。事件的可能性與支持判斷的信心分開寫。
- 圖下至少一句解讀，不逐項重述圖上的方框與箭頭。完整文字替代在圖旁給入口，不放進標「不必讀」卻有讀者必需的地方。
- 刪掉不改變判斷的句子：後設開場、作業流水帳、沒有對象的免責、疊加的模糊詞（examples「AI 常犯問題」）。推理依據要寫。真的不確定就說清楚哪裡不確定，給得出數字就給數字。
- 數字只留支撐主要訊息所需的那幾個，取整數要能對回原數。
- 只寫材料有的：材料沒提供的（分布、顯著性、驗證歷程）寫「材料未提供」，不為了解釋順而補。給人讀的每個主張都能對回查證用的部分。
- 一個項目承載一個完整主張，限的是主張數不是字數。不砍連接詞與主詞，不用符號串接敘事。
- 術語由上往下試：能換成日常說法且不失真就換。換不掉就保留，首次出現給一句白話說明。大型文件才建詞彙表。正式名稱留著當查詢入口。縮寫與代號首次出現給定義，表格與跨文件不豁免。
- 引用（examples）：連結文字描述目的地，直接引用加引號並標出處，引用其他文件說明它是否仍有效。「上週」「最近」改成絕對日期，狀態型文件標日期與狀態。
- 中文：台灣正體中文與台灣慣用語，Log、Endpoint 這類工程慣用英文不硬翻。標點細則見 examples。

## 5. 轉寄或貼到其他工具時

會被轉發、或給主管與跨部門讀的分享版，照 examples「內部版轉分享版」裁切：無人稱事實句、詞彙以雙方共同場合出現過的為界、外流檢查必跑。確定要轉寄時寫一行附哪幾節與檔案。圖畫不出來時改給文字替代。

## 6. 交付前驗證

**每份都跑**，同時回答兩題且同等重要：哪裡可能失真？哪裡讓讀者更累？

1. 開頭在上限內，第一句交代決定或動作狀態。
2. 有可掃讀且不失真的路徑，用第 3 節的掃讀判準檢查。
3. 從任一小節開頭讀起，能重新定位。
4. 每個主張對照過五種限制。
5. 從來源沿用的術語有白話說明，縮寫有定義。
6. 每個預設展開的區塊都說得出怎麼幫讀者完成當前任務，說不出就刪或移。同一事實沒有在主線重講。
7. 重讀最長的三個段落與三個條列項目，第一句之後每句都在補必要條件、理由或動作。
8. 分號、破折號、符號串接與中國用語。

**有條件才跑**：

- 分兩部分：請目標讀者只讀上方，回答「結果是什麼、現在能做什麼、還不能做什麼」，自己複述不算，沒拿到回答標「複述待驗」並附三題。講錯先找原因，不一律補限定語（examples 最後一節）。
- 有圖：圖標題、箭頭與正文一致，有文字替代。
- 操作型：最短成功路徑能照做完成。
- 改既有文件：照 examples「修改既有文件」，改了本文就同步開頭。

AI 看不到實際畫面時標「畫面待驗」並列出要看的項目（渲染、窄視窗、放大、對比、字型超框、複製結果）。

## 7. 規則衝突時

**預設好讀勝**。只有觸及底線時準確勝：限定語、前提或但書會改變讀者的判斷或行動，就緊貼主張留下，不會的移到查證用的部分或刪掉。

| 衝突 | 怎麼做 |
| --- | --- |
| 白話與忠於來源 | 換說法可以，不改數字、條件、範圍、因果方向與不確定性。做不到就兩個都寫，精確版放查證用的部分 |
| 限定語與一項一主張 | 底線內的限定語留下，放不下就改寫成段落 |
| 必要前提與精簡 | 只保護當前任務需要的前提，其他情境的例外照第 2 節分流 |
| 開頭上限與完整論證 | 上限勝，移走整個主張，限定語跟著主張走 |
| 自我完整與不重複 | 不重複勝，只留操作上必要的提醒（第 2 節）。圖上已畫的不逐項重述，圖意一句與底線內的限制仍留主線 |
| 通用慣例與讀者實際需求 | 讀者的任務、知識與實際回饋優先 |
