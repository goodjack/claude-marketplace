# 文件寫作風格

細節在 `references/`：`examples.md` 正反例、`doc-types.md` 各類文件骨架、`diagrams.md` 畫圖（要畫才讀）、`taiwan-terms.md` 用語詞表。

## 0. 目標、底線與必守條款

- **目標是好讀**：讀者省力地拿到需要的內容，找得到、看得懂、用得上。
- **底線是不失真**，只管會改變讀者判斷或行動的內容，也就是**五種限制**：
  1. 適用範圍：哪群人、哪段期間、哪些條件。
  2. 結論性質：相關還是因果、往回驗算還是預測。
  3. 證據可靠程度。
  4. 數字的必要背景：比較對象、期間、單位。
  5. 例外與不利結果，不能只留有利的。
- **底線以外，規則衝突時好讀勝**（第 7 節）。

必守條款：

1. 開頭有硬上限（第 2 節），放不下的移到後面小節，不刪。
2. 每個主張都對照五種限制，會改變判斷的才用一句白話寫在主張旁。
3. 分成兩部分或附摘要時，給人讀的部分或摘要能單獨正確使用，且與查證用的部分不矛盾。
4. 交付前跑第 6 節每份都跑的驗收，做不到的標待驗。

## 1. 先認定閱讀任務

- 單一目標讀者與他讀完要做的事：決定、操作、理解或查閱。這是寫作者的判斷，不一定寫進成品。
- 需求不明時，不同解讀會寫出實質不同的文件才先問，否則寫明假設繼續。
- 解釋多深看讀者對這個題目的熟悉度，不看職稱。研究與調查型產出預設讀者不熟。
- 對非實作讀者，用他看得到的結果取代實作機制名詞。
- 預設語氣是懂技術的同事向主管與團隊說明狀況（examples「語氣校準」）。
- 專案或團隊的寫作規範優先於本 skill，本 skill 優先於通用慣例。

## 2. 安排最少必要內容

**開頭**（同步層：標題後到第一個 `##` 前）最多 5 個主張，hook 量 400 字元。前兩句交代發生什麼、寫給誰、讀完要做什麼，再接要決定的事或結論。讀者已知的背景一句帶過，結論不晚於第二段。

待決事項多時，讓讀者知道全部範圍並能直接跳到清單。每個主張帶著自己的數字、條件與不確定性。

超過上限就把整個低優先主張移到後面小節，不拆限定語、不用多層子句硬塞。不出現本文件首次定義的術語。

其餘內容依類型決定去處：

| 類型 | 判準 | 處理 |
| --- | --- | --- |
| 主線 | 完成當前任務需要的判斷、步驟、前提與理解結果所需的說明；會改變判斷或操作的成本、安全、正確性限制；會影響結論、信心或行動的未知 | 緊接開頭 |
| 條件式 | 只有某些情境用得到 | 留觸發條件與一句摘要，細節後置 |
| 查閱型 | 讀者會回頭查（故障排除、參數表） | 主線後方或獨立文件 |
| 背景 | 不影響完成任務的設計理由 | 刪掉或移到設計文件 |

- 刪與移分開：理解需要的內容只移不刪。
- 查證細節與決策背景在支援收合的平台預設收合，會改變判斷的內容不收（examples「收合」）。
- 教學與操作型先給最短成功路徑：詞彙表、架構與故障排除不擋在第一次成功之前。寫操作或教學前必讀 `doc-types.md`「操作」：步驟照做不用判斷，前提集中在「開始前」。例外與未定的邊界放在讀者套用之前。
- 同一個事實的完整數字與證據只寫一次，結尾不重講。
- 各類文件（含工單與待裁決 Issue）的骨架見 `doc-types.md`，是鷹架不是範本，不適用的節省略。
- 要讓人理解、複述或轉述，又要保留精確版時才分兩部分：給人讀的在上，分隔線後第一個非空行固定以「以下供查證」開頭，查證用的在下。主要拿來查的文件（狀態、規格、決策紀錄）不分。
- 不設固定篇幅。太長時依序：細節移到後面、刪重複、最後才刪事項。因果與轉折的連接句不刪，必要判斷不移進不必讀的部分。總覽或首頁一頁看完，逐項細節移到子頁。

## 3. 選擇呈現方式

反覆查閱或跨文件比對的文件（報告、狀態、規格、決策紀錄）一律掃讀型，論述型只限一次讀完的說服文。**掃讀型的判準**：只讀標題與每段首句，就取得當前任務需要的資訊且不誤解。分析與決策型給判斷，操作型給動作，查閱型給定義或查找入口。

| 內容 | 形式 |
| --- | --- |
| 可重排的並列項目 | 條列，每項自我完整 |
| 有順序的步驟 | 編號清單 |
| 多屬性比較、要查確切數字 | 表格，儲存格精簡。要寫句子就改用一項一塊的條列 |
| 分支、迴圈或系統關係，且圖能降低理解成本 | 圖 |
| 要看趨勢、模式或例外的數字 | 圖表 |
| 強調先後的事件，三件以上 | 時間線，步驟不用 |
| 因果推導、權衡、連續推理 | 短段落 |

- 一段聚焦一個問題，約畫面三行（約 120 字）內，開頭更短，但不為了短切斷因果。
- 短文件不分節。標題用讀者熟悉的書面短語，讓人知道為什麼要看這節，不用問句、金句、內部詞或行話。操作指南的章節可寫成要完成的事。表格欄名用書面名詞（症狀、原因、處理）。
- 每段至多一個段首粗體短語，句子中間不加粗。短段落加粗體開頭是預設的掃讀形式。同一清單的格式一致。
- 指令、路徑、設定值放程式碼區塊，敘述段落少夾行內程式碼。要對照的項目（Endpoint、路徑、行號）用固定格式子項目一行一個，不用頓號串在句中。
- 同一份文件的視覺記號一致，需要解讀的記號（線型、顏色）附圖例，顏色不單獨承載意義。

對話裡的回覆：短回覆用段落、不加標題，第一句交代答案、現況與要不要行動。面向多到讀者要逐項對照，才用條列或表格。長任務的最後一則要能單獨讀懂。

## 4. 寫得清楚且不失真

- 不貼「已觀測、推論、已驗證、尚未定案」這類標籤或括號標註。只在會改變讀者決定的地方，用一句自然的話講確定程度，整份少量。會影響決定的推論仍要讓讀者知道還沒驗證。
- 只看到先後就寫先後，不升成因果。事件的可能性與支持判斷的信心分開寫。標題、粗體句、圖標題、方框與箭頭不能比材料更確定。
- 圖下至少一句解讀，不逐項重述，文字替代在圖旁給入口。
- 刪掉不改變判斷的句子：後設開場、作業流水帳、沒有對象的免責、疊加的模糊詞（examples「AI 常犯問題」）。推理依據要寫。真的不確定就說清楚哪裡不確定，給得出數字就給數字。
- 數字只留支撐主要訊息的，取整數要能對回原數。
- 只寫材料有的：缺口會影響判斷時寫「材料未提供」（例如分布、顯著性），不為了解釋順而補。給人讀的每個主張都能對回查證用的部分。
- 一句一件事，一個項目一個完整主張，不用一行片段取代完整句子。保留「因為、所以」這類連接詞與主詞，不用符號串接敘事。
- 術語由上往下試：能換成讀者平常講的詞且不失真就換，不是字面中譯或自創譯名，產品與系統用團隊慣用名稱。換不掉就保留，首次出現給一句白話說明，正式名稱留著當查詢入口。縮寫與代號首次出現給定義，表格與跨文件不豁免。
- 給人讀的部分不出現讀者手上沒有的文件、內部編號、工具欄位與作業狀態詞（examples「術語處理」）。
- 引用（examples）：連結文字描述目的地，直接引用加引號並標出處，引用其他文件說明它是否仍有效。「上週」「最近」改成絕對日期。
- 中文：台灣正體中文與慣用語，工程慣用英文（Log、Endpoint）不硬翻。標點細則見 examples。

## 5. 轉寄或貼到其他工具時

會被轉發、或給主管與跨部門讀的分享版，照 examples「內部版轉分享版」裁切：無人稱事實句、詞彙以雙方共同場合出現過的為界、外流檢查必跑。

## 6. 交付前驗證

**每份都跑**，同時回答兩題且同等重要：哪裡可能失真？哪裡讓讀者更累？

1. 開頭在上限內，第一段交代發生什麼與結論或要做的事。
2. 有可掃讀且不失真的路徑，用第 3 節的掃讀判準檢查。
3. 每節能單獨讀，沒有「上面、上一節」這類指代。
4. 每個主張對照過五種限制。
5. 術語是讀者平常講的詞或有白話說明，縮寫有定義，沒有讀者手上沒有的文件、編號與作業狀態詞。
6. 每個預設展開的區塊都說得出怎麼幫讀者完成當前任務，說不出就刪、移或收合。完整數字與證據沒有重講。
7. 重讀最長的三個段落與三個條列項目，第一句之後每句都在補條件、理由或動作。
8. 分號、破折號、符號串接與中國用語。

**有條件才跑**：

- 分兩部分：請目標讀者只讀上方，回答「結果是什麼、現在能做什麼、還不能做什麼」，自己複述不算，沒拿到回答標「複述待驗」並附三題。講錯怎麼改見 examples 最後一節。
- 有圖：圖標題、箭頭與正文一致，有文字替代。
- 操作型：最短成功路徑能照做完成。
- 改既有文件：照 examples「修改既有文件」，改了本文就同步開頭。

交付物依賴渲染而 AI 看不到畫面時，標「畫面待驗」並列出要看的項目（窄視窗、對比、字型超框、複製結果）。

## 7. 規則衝突時

**預設好讀勝**。只有觸及底線時準確勝：限定語、前提或但書會改變讀者的判斷或行動，就緊貼主張留下，不會的移到查證用的部分或刪掉。

| 衝突 | 怎麼做 |
| --- | --- |
| 白話與忠於來源 | 換說法可以，不改數字、條件、範圍、因果方向與不確定性。做不到就兩個都寫，精確版放查證用的部分 |
| 限定語與一項一主張 | 底線內的限定語留下，放不下就改寫成段落 |
| 開頭上限與完整論證 | 上限勝，整個主張移到後面小節，限定語跟著主張走 |
| 自我完整與不重複 | 理解當下所需的一句摘要可留，完整數字與證據不重講 |
| 通用慣例與讀者實際需求 | 讀者的任務、知識與實際回饋優先 |
